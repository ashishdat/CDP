Architecture and stage contracts

Input identity ? page routing ? registration ? candidates ? evidence ? claim decision. Recovery returns fresh evidence to the failed stage; it never sets acceptance. A verified non-claim page becomes a bundle attachment, while unverified roles stay visible in the audit.

Qualification on truly independent samples

  1. Create a new immutable cohort with no overlap by source hash or bundle with tuning samples
  2. Independently adjudicate each critical field and verify page roles; retain uncertain labels separately
  3. Freeze template, models, recovery policy, calibration, profile and tool capabilities before inference
  4. Run fresh output directories; do not merge old forced-CMS or candidate-only STP rows with new automatic-classification outcomes
  5. Report STP/HITL/stage failures/non-claim candidates on all selected documents; claim-only metrics require verified roles
  6. Audit accepted-field errors and false accepts, and stratify by family, handwriting, scan geometry, field and source pool
  7. Measure latency, model memory, timeout rate, recovery attempts and cloud cost only for authorized capabilities

Fresh qualification requires a new output directory. Existing ledgers without a matching run contract cannot be resumed under the new classification and acceptance rules.

Practical limits

  • Historical reports are secondary summaries; original Independent-600/400 ledgers are unavailable in this checkout
  • The two residual registration samples still fail geometry checks
  • Missing corroborating evidence and independent labels cannot be repaired by lowering acceptance thresholds
  • New recovery plans annotate and route failures; no additional automatic inference was launched
