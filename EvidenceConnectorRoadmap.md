# Evidence Connector Roadmap

Assessment date: 2026-09-14. Repository: `ashishdat/CDP`, branch `feature/cdp-v3`.

This is a design and source-readiness inventory only. Evidence Graph, nodes, edges, confidence, scoring, Auto Adjudication and runtime remain frozen. No connector was enabled, no enterprise system was queried, and no claim was rerun.

The repository contains reusable reference interfaces, matching services, snapshot support and a read-only finalized-claims SQL connector. This does **not** establish operational data access. All five providers in [reference_enrichment.yaml](config/reference_enrichment.yaml) are disabled and marked unauthorized. `config/reference_snapshots` contains a README but no data snapshots at the configured location. External credentials, customer entitlements and production source availability were not tested.

?Available? below distinguishes existing implementation/public distribution from an authorized source usable by CDP today. ?Expected independence? is a conditional provenance assessment, not a measured probability or a new graph score. The previous graph's absence of independently established evidence does not prove statistical dependence between every observation.

## Connector inventory

Effort estimates are planning judgments in engineer-days for one source and one bounded integration, including mapping, provenance, tests and a read-only pilot. They assume an accessible, documented source and exclude procurement, access approval, clinical/payer policy authoring, and historical-data remediation. Estimates are not measured ROI or delivery commitments.

|---|---|---|---|---|---|

Original scans or free-text notes are unstructured and cannot become independent truth merely by re-extraction. | Conditional medium?high for independently verified prior facts. Low/none for CDP predictions, copies of the current claim, or corrections accepted without independent review. The local checksum is not a registry lookup. AMA content access should be confirmed through the organization's existing entitlement; none was inspected here.

## Connector design using existing contracts

Use the existing [ReferenceLookupRequest and ReferenceRecord](packages/reference_enrichment/contracts.py), [ReferenceProvider implementations](packages/reference_enrichment/providers.py), and [snapshot contract](packages/reference_data/snapshot.py). Do not introduce another graph model, confidence formula or source-voting mechanism.

1. **Request and identity:** use the existing request's document, page, field, identity key, claim attributes and policy version. Bind enterprise queries to their configured tenant/source scope. Preserve the fact that lookup keys came from OCR. Record ambiguity instead of choosing a reference record simply because it agrees with the candidate.
2. **Independent source record:** return each source record separately, retaining source record ID, provider, dataset version, response hash, snapshot checksum, timestamps, field values and source lineage. Preserve disagreements and multiple results. A connector does not overwrite the extraction, approve a claim, or merge source values.
3. **Temporal meaning:** preserve effective-date information in source attributes and the applicable code/template/policy release. Distinguish lookup time from when a fact was valid. Historical snapshots must remain reproducible; ?latest? is not automatically correct for an older service date.
4. **Authority and lineage:** verify existing `independent_truth` and `non_circular_lineage` assertions against source ownership and provenance. Flags alone are not proof. Explicitly identify CDP-originated records, OCR-derived master data, source echoes and shared upstream databases. Exclude evaluation labels as production reference inputs under the existing contract.
5. **Availability:** distinguish disabled source, unauthorized access, lookup failure, missing record, multiple matches and contradictory record using existing provider/readiness and decision contracts. No result is not corroboration; absent confidence remains absent. Do not turn source uptime or lookup success into field confidence.
6. **Output boundary:** first retain standalone reference records and their audit references outside frozen runtime. This roadmap does not propose changing EvidenceNode, EvidenceEdge or EvidenceConfidence. Any later connection to the frozen application is a separate review, using existing contracts rather than changing graph algorithms.

Historical Claims means prior finalized field facts; Claim History means event chronology and downstream outcomes. They may come from the same system. A separate connector name, transport, snapshot or timestamp does not create a separate independent source.

## Proposed delivery order

This order balances access feasibility, fact relevance and conditional business value; it is not a measured expected-gain ranking.

| Sequence | Workstream | Concrete readiness outcome |
|---|---|---|
| 1 | NPI Registry pilot; request provider/member source access in parallel | Versioned external lookup evidence and documented lineage; enterprise owners confirm available fields and service-date semantics. No connector activation yet. |
| 2 | Member Registry and Provider Registry | One scoped source each, correct identity binding, temporal coverage and source-provenance review. Do not count a provider directory's NPPES mirror twice. |
| 3 | ICD and CPT reference snapshots | Authorized, checksum-verified releases selected by relevant date, with existence/validity evidence clearly separated from clinical correctness. |
| 4 | Historical Claims and Claim History | Original source lineage, independently finalized records, corrections and reversals represented explicitly; reject circular CDP-derived evidence. |
| 5 | Payer Rules and Template Version History | Bounded payer/product rule scope and authoritative form-version catalog; catalog missing assets without changing qualification rules. |

The key prerequisite is **source access and provenance**, not more graph computation. Member/provider registries are promising factual corroborators, while code, payer and template references address narrower rule or design questions. None is assumed to increase Auto Verification until usable, non-circular evidence exists for the actual field.

## Evidence needed before activation

For each proposed connector, demonstrate successful lookup, no match, ambiguous match, contradictory match, stale/version-mismatched records and unavailable-source handling against authorized source fixtures or a read-only pilot. Confirm stable source hashes, retained lineage and no source writes. These are future connector acceptance checks, not tests executed by this documentation task.

Measure lookup coverage, source-record applicability, temporal coverage and independently established provenance separately. Do not promise an operational completion gain from source availability alone, and do not require a graph or scoring change to declare a connector ready for review.

## Repository basis and limits

- [Reference data contract](config/reference_data_contract.yaml): member master, provider directory and previously validated claims; prohibits evaluation truth as a runtime reference.
- [Enrichment configuration](config/reference_enrichment.yaml) and [verification policy](config/reference_verification_policy.yaml): disabled providers, authorization and non-circular-origin requirements. Existing matching thresholds are unchanged.
- [Member/provider interfaces](packages/reference_providers.py), [read-only finalized-claims adapter](packages/downstream_claims_connector.py), and [snapshot readiness checks](packages/reference_data/readiness.py): implementation availability only, not live connectivity certification.
- [ICD](packages/validation_rules/icd10.py), [procedure-code](packages/validation_rules/cpt_hcpcs.py), and [NPI](packages/validation_rules/npi.py) implementations: local syntax/checksum checks do not constitute external reference confirmation.
- [Payer matching](packages/reference_enrichment/payer_matching.py): identity matching, not a complete payer adjudication-rule feed.
- [CMS1500 version metadata](templates/cms1500/version.json): evidence of the current reference's recorded provenance, not a complete independently certified version archive.
